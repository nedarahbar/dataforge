## ۲. پیش‌نیاز اجرا


## ۴. سناریوهای تست (گام‌به‌گام)

### سناریو ۱ — آپلود موفق CSV کثیف

**هدف:** اطمینان از پذیرش فایل معتبر و ثبت در Database

**مراحل:**

1. سرور را بالا بیاورید.
2. فایل `customers_test_dirty.csv` را آپلود کنید:

```bash
curl -X POST http://localhost:8000/datasets/upload \
  -F "file=@test_data/customers_test_dirty.csv"
```

3. پاسخ را بررسی کنید.

**نتیجه مورد انتظار:**

- HTTP Status: `201 Created`
- فیلدهای `dataset_id`, `filename`, `file_type=csv`, `rows`, `columns`, `status=UPLOADED`
- `rows` باید برابر تعداد ردیف‌های داده (بدون Header) باشد

**نمونه پاسخ:**

```json
{
  "dataset_id": 1,
  "filename": "customers_test_dirty.csv",
  "file_type": "csv",
  "rows": 19,
  "columns": 11,
  "status": "UPLOADED"
}
```

`dataset_id` را برای مراحل بعد نگه دارید (اینجا فرض می‌کنیم `1`).

**چک‌پوینت‌های دستی:**

- [ ] Duplicate شناسایی شده
- [ ] Missing شناسایی شده
- [ ] برای ستون `age` آمار عددی وجود دارد

### سناریو ۸ — اجرای Cleaning Pipeline

**هدف:** پاک‌سازی Configurable

```bash
curl -X POST http://localhost:8000/datasets/1/clean \
  -H "Content-Type: application/json" \
  -d '{
    "remove_duplicates": true,
    "fill_missing": true,
    "normalize_text": true,
    "validate_values": true,
    "detect_outliers": true,
    "numeric_strategy": "median",
    "categorical_strategy": "mode"
  }'
```

**نتیجه مورد انتظار:**

- HTTP `200`
- `status = CLEANED`
- `duplicates_removed > 0`
- `missing_values_filled > 0`
- `invalid_values_detected >= 1`
- `outliers_detected >= 1`
- `rows_after < rows_before` (به‌خاطر حذف Duplicate)

**چک‌پوینت‌ها:**

- [ ] Duplicateها حذف شده‌اند
- [ ] Missingهای قابل پر شدن پر شده‌اند
- [ ] شهرهای ناسازگار یکدست‌تر شده‌اند (مثلاً به سمت `Tehran`)
- [ ] Outlier فقط گزارش شده و لزوماً حذف نشده

### سناریو ۹ — گزارش کیفیت (Before / After)


**نتیجه مورد انتظار:**

- HTTP `400`
- کد: `DATASET_NOT_CLEANED`


**نتیجه مورد انتظار:**

- HTTP `204 No Content`
- بعد از حذف، `GET /datasets/1` باید `404` بدهد

### سناریو ۱۴ — تست از طریق Swagger UI

**مراحل:**

1. بروید به `http://localhost:8000/docs`
2. بخش `Datasets` را باز کنید
3. `POST /datasets/upload` → `Try it out` → انتخاب `customers_test_dirty.csv` → Execute
4. `dataset_id` را کپی کنید
5. به ترتیب: `profile` → `clean` → `quality` → `analysis` → `download`
6. در پایان `DELETE` را امتحان کنید

**نتیجه مورد انتظار:** همه مراحل بدون خطای ۵۰۰ انجام شوند و Response Schema با مستندات هم‌خوان باشد.

### سناریو ۱۶ — گردش کامل با یک اسکریپت پشت‌سرهم

این سناریو کل Pipeline را در یک نشست بررسی می‌کند:

```bash
# 1) Upload
UPLOAD=$(curl -s -X POST http://localhost:8000/datasets/upload \
  -F "file=@test_data/customers_test_dirty.csv")
echo "$UPLOAD"
ID=$(python -c "import json,sys; print(json.loads('''$UPLOAD''')['dataset_id'])")

# 2) Profile
curl -s "http://localhost:8000/datasets/$ID/profile" | python -m json.tool | head

# 3) Clean
curl -s -X POST "http://localhost:8000/datasets/$ID/clean" \
  -H "Content-Type: application/json" \
  -d '{"remove_duplicates":true,"fill_missing":true,"normalize_text":true,"validate_values":true,"detect_outliers":true}' \
  | python -m json.tool

# 4) Quality
curl -s "http://localhost:8000/datasets/$ID/quality" | python -m json.tool

# 5) Analysis
curl -s "http://localhost:8000/datasets/$ID/analysis" | python -m json.tool | head -80

# 6) Download
curl -s -o /tmp/test_cleaned.csv -w "%{http_code} %{content_type}\n" \
  "http://localhost:8000/datasets/$ID/download"
head -5 /tmp/test_cleaned.csv
```

**نتیجه مورد انتظار:** همه مراحل موفق؛ فایل دانلودشده CSV معتبر.

## ۶. نتیجه مورد انتظار خلاصه

برای `customers_test_dirty.csv` بعد از Cleaning معمولاً انتظار دارید:

| شاخص | قبل (تقریبی) | بعد (تقریبی) |
| --- | --- | --- |
| Rows | ۱۹ (با Duplicate) | کمتر از ۱۹ |
| Duplicates | > ۰ | ۰ |
| Missing | > ۰ | نزدیک به ۰ |
| Invalid | سن/ایمیل/مقدار منفی شناسایی شود | گزارش شود |
| Outliers | حداقل ۱ مورد | گزارش شود (حذف اجباری نه) |
| Quality Score | — | عدد ۰ تا ۱۰۰ با تفسیر متنی |

> اعداد دقیق بسته به منطق Cleaning و ترتیب عملیات ممکن است کمی فرق کند؛ مهم رفتار صحیح API و گزارش شفاف است.

## ۷. عیب‌یابی هنگام تست

| مشکل | کار پیشنهادی |
| --- | --- |
| Connection refused | اول `uvicorn` را اجرا کنید |
| `DATASET_NOT_CLEANED` | قبل از quality/analysis/download حتماً `/clean` را بزنید |
| `DATASET_NOT_FOUND` | `dataset_id` اشتباه است یا Dataset حذف شده |
| آپلود شکست می‌خورد | مسیر فایل را نسبی از ریشه پروژه بدهید: `test_data/...` |
| Download باز نمی‌شود | Header و `Content-Disposition` را با `-i` ببینید |
